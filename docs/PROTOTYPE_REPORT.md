# 遊べるプロトタイプの実装・検証報告

## 2026-09-29：背後追従・戦場拡張・敵の階級

最新仕様は `GAME_SPEC.md` Version 1.2.0-battlefield。以下の過去記録にある単独の1,000体クリアや
66×66の戦場は改修前の内容。

- 進行方向へ滑らかに回る背後追従カメラ。Q/Eで旋回、Cで背後へ戻す。
- 入力開始時のカメラを基準にWASDを解釈し、キーを押し続ける間は進路を維持する。
  自動旋回で移動が円を描くのを防ぎ、攻撃の方向補助ではカメラを振り回さない。
- 210×210（従来の約10倍の面積）の寺院。中央と西院・東院・南庭を参道で接続。
  建物・塀・岩・門柱の衝突、壁沿い移動、攻撃遮蔽、敵の障害物迂回を実装した。
- 視点に合わせて回るミニマップ、拠点への方向と距離、討伐済み表示、近くの怨将のHPと攻撃警告。
- 雑兵HP35、武者180、重装兵450、怨将1,800。雑兵は通常一撃、上位ほど吹き飛びにくく、
  怨将は範囲予告付き攻撃を被弾で中断しない。各拠点に1体ずつ配置し、討伐後は再出現しない。
- クリア条件は1,000体撃破と怨将3体討伐の両方。リトライ時は討伐数・配置・体力もリセットする。
- キャラクターは仮モデルを継続使用。写実寄りの専用GLBと骨格アニメーションへの移行方針を
  `docs/ART_DIRECTION.md` に記載した。専用モデルの制作は未完了。

### 検証と修正

- 自動テストで通常一撃と上位耐久、怨将の予備動作・反撃、予約枠の非再利用、壁越し攻撃の遮蔽、
  全拠点間の到達性、壁際の追跡、方向入力とカメラ、HPバーの表示位置を確認。
- ステータスを変更しない移動・K/L入力によるシミュレーションで、三将討伐＋1,000体クリア、再挑戦、敗北まで確認。
- 内蔵ブラウザー1280×720で、中央から南庭へ通常入力で移動。中ボスHP1,800から討伐まで確認し、
  討伐数1/3、次の東院への案内、501撃破、プレイヤーHP870を画面で確認した。
- 同検証で敵70体・60 FPSを観測。Geometryはウォームアップ後47で安定した（最終の石材バッチ修正前）。
  自動操作用タブと別の内蔵タブでは描画が強く抑制される場合があり、全タブ・全端末の性能保証ではない。
- 独立レビューで、壁密着時にカメラの最短距離が壁内へ押し出す不具合を発見し修正。
  カメラの支点移動にも衝突を適用し、カメラが壁へ入るケースを回帰テストに追加した。
- 実画面でHPバーが手前で大きくなりすぎたため、距離で幅を制限し、通常の上位兵は被弾時のみ表示する。
- ブラウザーのconsoleから石材Geometry結合の形式不一致を発見。静的バッチを同じ形式へ揃えて修正し、
  描画構築の回帰テストを追加した。最終ビルドの再起動・戦闘で石畳・参道の描画と新規console error/warnなしを確認。
- 最終 `npm test`: **8ファイル・67件成功**。`npm run typecheck` / `npm run build` 成功。
  追加npm依存なし。JSは約643kB（gzip約166kB）で、Viteの500kBチャンク警告は残る。

通常の前面Chrome / Edge実機、長時間の負荷試験、完成版モデルでの描画負荷は未確認。

## 2026-09-29：無双らしい演出・操作感への改修

ユーザーの「見た目が地味」「爽快感がない」「三國無双・戦国無双が目標」という評価と参考画像に基づき、
戦闘と描画を改修した。最新の調整値は `GAME_SPEC.md` Version 1.1.0-musou-combat および `src/config/balance.ts`。
以降の初回実装記録にある50体上限・100体クリアなどは改修前の値。

- 初期50体、目標70体、固定96枠。接近速度と補充頻度を上げ、集団を攻撃できる時間を増やした。
- J長押しの3段連撃、前方の敵への方向補助、踏み込み、広い攻撃範囲。K・Lへの連携を優先できる入力バッファ。
- 敵の高さ・重力・回転を計算し、強攻撃と仏技で群れが実際に空中へ吹き飛ぶ。
- 命中時だけ短いヒットストップ、画角変化・振動、仏技時の短いスロー。停止中の入力を保持する。
- 各段の判定に合った金色の光弧、多層衝撃波、480枠のInstancedMesh粒子、仏技の大きな光輪。
- 仏像の衣のひだ、指、螺髪、光背、錫杖を拡充。敵は赤黒の甲冑。背景に寺院、旗、炎、煙、火の粉、石の質感を追加。
- 環境反射、接地影、ブルームを追加。静的形状の結合とInstancedMeshで描画数を抑える。
- 墨・朱・金のHUD、赤い体力と金の仏力、巨大COMBO、攻撃単位で累計するHit表示。
- Web Audioによる短い合成打撃音・仏技音。Mまたは「音」ボタンで切り替え。Pause/消音時は発音ノードを停止してから音声コンテキストを休止する。
- 強化後は100体が約7秒で終わったため、クリア条件を1,000体へ変更した。

## パフォーマンスとリソース

- 内蔵ブラウザーで敵50体、1920×1080: F3表示60 FPS、47 draw calls、31,500 triangles。
- 1280×720での戦闘中も約60 FPSを観測。個別端末での性能保証ではなく、この実行環境の観測値。
- Chromeの自動接続タブでは描画頻度が1 FPSに制限される状態があり、Chromeの前面実行時の性能値としては採用していない。
- 描画ループは全体で1本。敵個別のDOM、ループ、ライト、Raycasterは使用しない。
- 背景をマテリアルごとに結合し、敵パーツはInstancedMeshで共有する。
- エフェクトは攻撃8枠とヒット・死亡64枠に分け、閃光が重要な仏技リングを上書きしない。
- 戦闘を再開してもScene・Renderer・Meshを作り直さない。GPU Geometry数は初回使用で26から最大29へ増え、その後の再挑戦では増えない構成。
- 破棄時にDOMイベント、UIイベント、描画予約、共有Geometry / Material / InstancedMeshを解除。
- HUD更新は10 Hz、FPS等の集計は1 Hz。

修正後に同じ独立レビュアーがコードと回帰テスト9件を再確認し、指摘した不具合の解消を確認した。
